## 实施顺序

1. 先以失败测试固定模型、执行器、缓存、Provider 和 ViewModel 契约。
2. 实现 Core 业务逻辑，再实现 Windows 基础设施和 Provider。
3. 最后接入 WPF UI，确保 UI 只依赖统一快照。
4. 通过全量测试后发布 `win-x64` 构建，并进行真实应用启动检查。

## 风险与后续

- 三家 CLI 的交互提示和输出格式可能变化；Parser 已动态识别额度名，但仍需用真实版本样本持续补充 fixture。
- ConPTY 查询使用启动等待窗口，真实 CLI 若启动超过默认等待时间，需要增加 Ready prompt 检测。
- V1.1 可加入 JSON/Regex/PowerShell 自定义 Parser、历史记录和更多 Provider。
