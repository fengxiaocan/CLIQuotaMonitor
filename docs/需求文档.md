下面这份可以直接作为项目需求文档初稿。考虑到 Codex、Grok、Antigravity 的额度查询方式并不完全一致，我把核心设计成了“**CLI 额度适配器 + 可配置查询命令 + 统一额度模型**”，这样以后接 Claude Code、Gemini、Cursor CLI 等也不用重做悬浮窗。

# Windows CLI 额度监控悬浮窗需求文档

## 1. 项目概述

### 1.1 项目名称

暂定名称：

**CLI Quota Monitor**

中文名称可使用：

**CLI 额度监控器**

### 1.2 项目定位

开发一个运行于 Windows 10 / Windows 11 的轻量级桌面悬浮工具，用于统一查看本机多个 AI 原生 CLI 工具的账户额度、周期限额以及额度重置时间。

首期支持：

* OpenAI Codex CLI
* xAI Grok CLI / Grok Build
* Google Antigravity CLI
* 自定义 CLI

后续可扩展：

* Claude Code
* Gemini CLI
* GitHub Copilot CLI
* Cursor CLI
* OpenCode
* 其他可以通过命令、脚本、HTTP API 或本地文件获取额度信息的工具

软件无需代理 CLI 请求，也不接管 CLI 会话。

它只是一个：

**“读取额度 → 解析 → 统一展示”的桌面监控浮窗。**

---

# 2. 设计目标

核心目标：

1. 随时看到不同 CLI 剩余额度。
2. 不需要不断打开 CLI 输入 `/status`、`/usage`。
3. 可设置自动刷新周期。
4. 可选择显示哪些 CLI。
5. 可选择显示哪些额度周期。
6. 悬浮在桌面或者开发工具顶部。
7. 支持透明背景和紧凑布局。
8. 尽可能降低 CPU、内存及磁盘占用。
9. 不影响正在运行的 Codex / Grok / Antigravity 会话。
10. 查询异常不能导致 CLI 原来的登录状态失效。
11. 不依赖任何额外 API Key。
12. 默认复用用户原生 CLI 已有登录环境。

软件本质上类似：

> 网速 / CPU / GPU 性能悬浮窗

但展示的数据变成：

> Codex / Grok / Antigravity 等 AI CLI 的剩余额度。

---

# 3. 当前 CLI 查询能力设计依据

由于不同 CLI 的额度查询机制并不相同，程序不能假设所有 CLI 都存在：

```text
xxx quota --json
```

这样的统一接口。

因此必须采用适配器机制。

## 3.1 Codex CLI

Codex CLI 当前可以在 CLI 会话内通过：

```text
/status
```

查看账户状态和当前使用情况。OpenAI 官方文档目前仍将 `/status` 作为 Codex CLI 的状态查看入口，OpenAI 帮助中心也说明可以在正在运行的 Codex CLI 会话中通过 `/status` 查看限制和使用情况。([OpenAI Developers][1])

实际显示内容可能包含：

```text
5h limit
Weekly limit
Credits
reset time
```

但额度类别可能随着 OpenAI 政策和账户类型变化，因此不能在程序中硬编码“Codex 一定存在 5 小时额度”。

2026 年期间 Codex 的 5 小时窗口曾发生调整，因此软件应当把额度窗口作为动态数据解析，而不是写死。([OpenAI Developer Community][2])

建议 Codex Adapter 支持：

```text
Interactive CLI
PTY 查询
已有 CLI 状态读取
自定义查询脚本
未来官方 JSON 查询接口
```

---

## 3.2 Grok CLI

Grok Build 提供：

```text
/usage
```

以及：

```text
/cost
```

查看使用量。

官方项目文档说明 `/usage` 会打开账户 Usage 信息，同时：

```text
grok usage <session-id> [turn]
```

可以查询本地会话的 token / cost 信息。([GitHub][3])

因此 Grok Adapter 可以同时支持：

```text
账户额度
+
本地 Session 使用量
```

例如：

```text
Grok

Account
████████████░░░░ 73%

Current Session
2.3M tokens

Reset
03:42:18
```

需要注意：

**Session token 使用量和账户限额不是同一个概念。**

UI 中必须分开展示。

---

## 3.3 Antigravity CLI

Antigravity CLI 当前提供：

```text
/usage
```

以及：

```text
/quota
```

用于查看模型额度。

目前相关输出中可以出现：

```text
Weekly Limit
Five Hour Limit
remaining
refresh time
```

例如 Antigravity 官方项目 Issue 中记录的 `/usage` 输出包含 Weekly Limit 和 Five Hour Limit。([GitHub][4])

但需要特别注意：

目前：

```text
agy -p "/usage"
```

并不能简单等价于交互式 `/usage`。

相关官方项目 Issue 中就有人提出希望能够通过单命令获取 quota，因为 `agy -p "/usage"` 会被当作 Prompt，而不是 slash command。([GitHub][5])

因此 Antigravity 查询不能简单写成：

```text
Process.Start("agy -p /usage")
```

首版建议采用：

```text
PTY 启动 agy
↓
等待 CLI Ready
↓
发送 /usage
↓
读取终端输出
↓
解析额度
↓
发送 /exit
```

同时保留未来直接 CLI 查询接口。

# 5. CLI Adapter 适配器机制

这是整个项目最重要的模块。

每一个 CLI 都实现：

```text
IQuotaProvider
```

逻辑接口示例：

```csharp
interface IQuotaProvider
{
    string Id { get; }

    string DisplayName { get; }

    Task<bool> IsInstalled();

    Task<AccountInfo> GetAccount();

    Task<QuotaResult> GetQuota();

    Task<TestResult> Test();
}
```

例如：

```text
CodexQuotaProvider

GrokQuotaProvider

AntigravityQuotaProvider

CustomQuotaProvider
```

以后增加 Claude：

```text
ClaudeQuotaProvider
```

不需要修改悬浮窗。

# 6. 统一额度模型

所有 CLI 查询结果统一转换成：

```text
Provider

Account

Plan

Quota[]

LastUpdated

Status
```

Quota 数据：

```text
Name

UsedPercent

RemainingPercent

ResetAt

ResetAfter

Type
```

例如：

```json
{
  "provider": "codex",
  "account": "ChatGPT Account",
  "quotas": [
    {
      "name": "5h",
      "remaining": 72,
      "resetAfter": "02:43:18"
    },
    {
      "name": "weekly",
      "remaining": 43,
      "resetAfter": "3d 4h"
    }
  ]
}
```

这样 UI 完全不关心额度来自哪个 CLI。

# 7. 动态额度周期

程序禁止硬编码：

```text
5小时额度
Weekly
Monthly
```

Adapter 获取什么就显示什么。

例如某天 Codex 返回：

```text
5h
Weekly
Credits
```

则显示：

```text
Codex

5H       72%
Weekly   43%
Credits  120
```

如果之后变成：

```text
Daily
Weekly
```

UI 自动变成：

```text
Codex

Daily    72%
Weekly   43%
```

不需要更新客户端。

# 30. 倒计时

无需不断调用 CLI。

```text

```

例如：

```text

03:42:50

```

但是：

**CLI 查询依旧每 5 分钟一次。**

这样既有实时倒计时，又不会频繁启动 CLI。

# 40. 安全设计

**不保存账号密码。**

默认不读取：

```text
浏览器 Cookie
```

不上传：

```text
Token

Session

CLI Config

额度数据
```

到远程服务器。

所有数据：

```text
本机获取
本机解析
本机显示
```

# 71. 核心开发原则

项目实现时建议始终遵守四个原则：

**第一：不要依赖某一个 CLI 固定输出格式。**

采用 Provider + Parser 机制。

**第二：不要假设一定存在 5H / Weekly。**

额度窗口必须动态发现。

**第三：不要频繁启动 CLI。**

Quota 查询几分钟一次，Reset 倒计时本地计算。

**第四：不要修改 CLI 登录环境。**

只复用原生 Codex、Grok、Antigravity 已经存在的身份认证。

最终实现出来应该是一个真正可以长期挂在 Windows 桌面的轻量型：

**Codex / Grok / Antigravity CLI 额度监控悬浮窗。**

这里有一个实现层面很关键的点：**不要把第一版设计成“执行一条固定命令，然后正则解析三家 CLI”**。目前 Codex、Grok、Antigravity 的额度入口就已经存在明显差异，尤其 Antigravity 的 `/usage` 属于交互命令，简单执行 `agy -p "/usage"` 并不能可靠获得额度。([GitHub][3])

所以我更推荐第一版直接把 **Windows ConPTY + Provider Adapter + Parser** 这三个模块搭好。这样以后即使某个 CLI 的 `/status` 输出改变，也只是换解析器，不需要重写整个悬浮窗。
