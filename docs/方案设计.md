# CLIQuotaMonitor 方案设计

更新时间：2026-09-20

## 分层

```text
WPF App / Tray
        │ 只消费 QuotaSnapshot
        ▼
QuotaManager ── 单 Provider 并发门闩、缓存回退、错峰刷新
        │
        ▼
IQuotaProvider ── Codex / Grok / Antigravity Adapter
        │
        ├─ IQuotaParser ── 动态额度、Reset、SessionUsage
        └─ IQueryExecutor ── Command / ConPTY Router
                              │
                              ├─ CommandQueryExecutor
                              └─ ConPtyQueryExecutor (Windows API)
```

## 核心模型

- `QuotaItem`：名称、剩余百分比或数值、单位、`ResetAt`，本地计算 `ResetAfter`。
- `QuotaSnapshot`：Provider、账户/计划、动态 `Quotas`、状态、更新时间、陈旧标记和安全错误信息。
- `ProviderSettings`：启用状态、路径、查询方式、Command 参数、超时、排序和可见额度名。
- `AppSettings`：刷新、工作时间、窗口、通知、开机启动和 Provider 配置。`WorkTimeSettings` 保存启用状态、`HH:mm` 开始/结束时间和选中的 `DayOfWeek`。

## 查询流程

1. Timer 先检查自动刷新开关和 `WorkTimePolicy`；不在工作时间时不启动 CLI 查询。刷新按钮或托盘动作直接作为手动刷新进入 `QuotaManager`，不受工作时间限制。
2. 仅刷新启用的 Provider，并按排序依次错峰 3 秒。
3. Provider 通过 `ExecutableResolver` 解析配置路径、PATH 和常见安装目录。
4. `Auto` 选择 PTY；`Command` 使用独立的 stdout/stderr 重定向子进程。
5. `Pty` 创建 Windows ConPTY，等待 CLI 启动后发送 slash command，再发送退出命令。
6. Parser 删除 ANSI 控制码，提取动态 quota；没有有效 quota 时返回 `ParseError`。
7. 成功结果写入 JSON 缓存；失败时返回带 `IsStale=true` 的最近成功结果。
8. UI 每秒只更新 Reset 倒计时，不重复启动 CLI。

## 安全与性能

- 查询只启动新的子进程，不使用用户正在运行的 CLI 会话。
- `LogRedactor` 对 Bearer、api_key/token/secret 和 `sk-` 形式的内容脱敏。
- 错误消息不保留原始敏感 stderr；配置/缓存为本地 JSON，无数据库和网络服务。
- Provider 查询单飞；默认刷新 5 分钟，查询默认超时 10 秒。
- 窗口使用事件驱动绑定，只有 Reset 倒计时使用 1 秒 DispatcherTimer。

## Windows 集成

- `NotifyIcon` 提供系统托盘入口。
- `WindowsStartupManager` 写入当前用户 `Run` 键，启动项附带 `--startup`，启动后直接隐藏浮窗并保留托盘。
- 窗口坐标、透明度、置顶和锁定状态在退出时保存。
